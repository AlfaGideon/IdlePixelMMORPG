# IdlePixelMMORPG — план разработки

**Статус:** черновик v0.1 (обсуждается)
**Дата:** 2026-11-02
**Движок:** Defold 1.14.x (Lua)
**Платформы:** Android (APK), Web (HTML5). iOS — вне скоупа.
**Ориентация:** динамическая — портрет и ландшафт, UI подстраивается.
**Монетизация:** внешняя (вне сторов), без IAP.

## 1. Питч в одном абзаце

Идл-RPG, где игрок — смотритель аванпоста на краю распадающегося мира. Аванпост в автоматическом
режиме добывает ресурсы, крафтит снаряжение и отправляет экспедиции, пока игрок офлайн.
Но мир общий: добытые ресурсы идут в общий щит сервера против «Волн Пустоты», раз в несколько часов
приходит мировой босс, а снаряжение продаётся на общем аукционе. Игра живёт в 10–60-секундных сессиях
на телефоне, но при этом это настоящий общий мир с другими игроками.

**Почему именно так:** idle-механика — это ровно то, что не ломается при мобильных разрывах связи
и закрытом приложении. MMO-слой даёт причину возвращаться и социальную привязку, но не требует
боевого netcode в реальном времени — самая дорогая часть MMORPG вырезана, а ощущение мира осталось.

## 2. Платформы, распространение, ограничения

### 2.1 Что реально собираем

| Платформа | Как собирается | Кто делает | Где раздаём |
|---|---|---|---|
| **Web (HTML5)** | `bob.jar` + Emscripten SDK, CI на ubuntu | автоматически | свой домен, itch.io |
| **Android APK / AAB** | `bob.jar` + Android SDK/NDK + JDK 21, CI на ubuntu | автоматически | прямая ссылка, RuStore, Google Play (см. §6.4) |
| **iOS** | только macOS + Xcode | — | **не делаем** |

### 2.2 Честные ограничения

- **В песочнице, где пишется код, собрать Defold-проект нельзя** (нет JDK и доступа к CDN сборщика).
  Поэтому: исходники и локальный сервер — здесь, а сборки APK/Web — в GitHub Actions.
  Для проверки геймплея без Defold Editor делаем отладочный веб-клиент (§4.4).
- **Web на мобильном браузере** — самый капризный таргет: wasm-бандл, блокировка звука до первого тапа,
  лимиты памяти в мобильном Safari. Web-версия позиционируется как «лайт-клиент», не как основной способ играть.
- **Без iOS** отпадает половина нативной возни: нет сертификатов, provisioning profiles, App Store Review.
  Это экономит недели. Архитектура при этом не мешает добавить iOS позже (клиент уже на Defold).

### 2.3 Dynamic orientation: что подтверждено в движке

- `display.dynamic_orientation = 1` в `game.project` → Android-манифест получает `fullUser`
  (в исходниках `AndroidBundler.java` при выключенном флаге жёстко ставится `userPortrait`/`userLandscape`
  в зависимости от `display.width/height`).
- Разворот приходит в клиент как `window.WINDOW_EVENT_RESIZED`; пересчёт layout — на нашей стороне.
- Растягиваемые панели — nine-slice (`gui.set_slice9`), без него мобильный UI выглядит мылом.

## 3. Концепт игры (прототипа нет — проектируем с нуля)

### 3.1 Сеттинг и фантазия

Мир распадается: по его краям наступает Пустота. Игрок — смотритель одного из аванпостов на границе.
Аванпост — это не «герой», а маленькая экономика: лесопилка, шахта, кузница, сторожевой пост.
Игрок не бегает по миру, он **принимает решения** и **ставит очереди**, а аванпост работает сам.

Ключевая эмоция: «мой маленький завод растёт, и его продукция реально нужна другим».

### 3.2 Три петли

**Микро (10–60 сек, каждая сессия):**
зайти → забрать накопленное → потратить на апгрейд/крафт → поставить новую очередь → выйти.

**Мезо (1–3 дня):**
новый тир материала → новый инструмент → выше доход → открывается новая зона/профессия.

**Макро (недели, общее для сервера):**
волны Пустоты → общий щит мира → мировые боссы → сезонный сброс щита и награды по вкладу.

### 3.3 Профессии (ядро MVP — 4)

| Профессия | Ресурс | Куда идёт |
|---|---|---|
| Лесоруб | Древесина | инструменты, стрелы, щиты |
| Шахтёр | Руда | снаряжение, механизмы |
| Рыбак | Рыба | еда/баффы, алхимия |
| Травник | Травы | зелья, зелья опыта |

Каждая профессия: уровень 1..100, скорость добычи растёт от уровня и инструмента.
Параллельно качаются все четыре, но активных «слотов работы» на старте — 2.
Слоты открываются уровнями аванпоста и покупками во внешнем магазине (§6).

### 3.4 Ресурсы и тиры

6 типов материала × 5 тиров на MVP:

```
Тир 1: Дуб / Медь / Окунь / Ромашка
Тир 2: Железное дерево / Железо / Щука / Полынь
Тир 3: Сребролист / Серебро / Осётр / Лунный цвет
Тир 4: Обсидиан / Мифрил / Светящийся скат / Пепельная трава
Тир 5: Мировое древо / Звёздный металл / Левиафан / Цветок Пустоты
```

Тир открывается уровнем профессии (15/30/50/75) и требует постройки в аванпосте.
Добыча более высокого тира медленнее, но ценнее — это создаёт вертикаль.

### 3.5 Крафт и очередь работ

Крафт идёт **по времени**, а не мгновенно — это главный источник «возвращений» в течение дня.

| Действие | Длительность | Результат |
|---|---|---|
| Инструмент | 5 мин – 2 ч | множитель добычи +15–60% |
| Снаряжение | 10 мин – 4 ч | боевая мощь для боссов |
| Зелье/еда | 1–30 мин | временные баффы (в т.ч. оффлайн-доход) |
| Экспедиция | 15 мин – 8 ч | редкие материалы + очки вклада |

Одновременно 1 очередь крафта (2-я — за вклад/покупку). Очередь хранится на сервере.

### 3.6 Оффлайн-прогресс и серверное время

Всё считается на сервере по времени последнего действия:

```
накоплено = ∫ скорость(t) dt  ≈  скорость_на_момент_ухода × elapsed_seconds
elapsed = min(now_server − last_collect_at, cap)
cap = 8 ч (базовый), 12 ч (буст из внешнего магазина)
```

- Клиент **не присылает** «сколько прошло» и «сколько начислено».
- Клиент присылает только намерение: `collect`, `upgrade`, `craft_start`, `expedition_start`.
- Часы устройства игрока не участвуют в расчётах никогда.

### 3.7 Первые 30 минут (сценарий онбординга)

| Время | Что происходит |
|---|---|
| 0:00–0:30 | Логин без пароля (ник + код устройства → токен). Сразу видно аванпост и таймер добычи |
| 0:30–2:00 | Один тап «Начать добычу» → ресурсы капают. Туториал: «закрой игру, вернись — будет больше» |
| 2:00–5:00 | Первый апгрейд инструмента, открывается второй слот профессии |
| 5:00–10:00 | Первый крафт (5 минут), первая экспедиция на 5 минут |
| 10:00–20:00 | Открывается аукцион и чат — видно живых людей (важнейший момент удержания) |
| 20:00–30:00 | Первая Волна Пустоты: общий прогресс-бар, вклад, награда по вкладу |

К 30-й минуте игрок должен: иметь 2 профессии, 1 крафт, 1 экспедицию, 1 вклад в общее событие
и понимать, что вернуться стоит через 2–3 часа.

### 3.8 MMO-слой: что общего и что личное

| Система | Тип | Итерация |
|---|---|---|
| Общий шард, видно других игроков у аванпоста | общая | 3 |
| Мировой чат + личные сообщения | общая | 2 |
| Аукцион (листинги, комиссия 5%) | общая | 3 |
| Волна Пустоты: общий прогресс-бар сервера | общая | 3 |
| Мировой босс по расписанию, урон от боевой мощи, награда по вкладу | общая | 3 |
| Гильдии / кланы с общими целями | общая | 4 (post-MVP) |
| PvP-дуэли «призраками» (асинхронно) | общая | 4 (post-MVP) |

**Важно:** MMO-слой не требует real-time боя. Обновление позиций/чата — редкие сообщения (1–5 в секунду),
боевые события — расчёт по вкладу, а не по тикам.

### 3.9 Баланс: стартовые числа (черновик, правится симулятором)

```
скорость(проф, lvl) = base × 1.28^(lvl−1) × tool_mult × buff_mult
base = 1 ресурс / 12 сек
XP до уровня      = 100 × 1.15^(lvl−1)
цена апгрейда     = 50 × 1.6^tier × 1.25^lvl
доход оффлайн     = 60% от активной скорости (100% с премиум-бустом)
мировой босс HP   = 500 000 × (1 + 0.35 × номер_босса), урон = боевая мощь × 100
```

Проверка баланса — не «на глаз», а отдельным скриптом-симулятором (§4.5):
прогон 30 дней прогресса для 4 архетипов игрока (казуал 2 сессии/день, активный 8 сессий/день, кит, f2p).

## 4. Клиент: Defold

### 4.1 Структура проекта

```
client/
  game.project
  input/game.input_binding
  main/            -- загрузка, логин, роутинг экранов
    main.collection
    main.script
  screens/
    camp/          -- аванпост (главный экран)
    skills/        -- профессии
    craft/         -- крафт и очередь
    shop/          -- аукцион
    chat/          -- чат
    world/         -- карта/события
  ui/              -- наша layout-библиотека (см. 4.2)
  net/             -- websocket-клиент, очередь интентов, реконнект
  data/            -- сгенерированные из shared/configs Lua-таблицы
  art/             -- атласы, nine-slice панели, шрифты
```

### 4.2 Своя layout-библиотека (самая большая часть клиента)

В Defold нет готового UI-фреймворка, поэтому пишем минимальный retained-UI:

- **Контейнеры:** `row`, `column`, `grid`, `stack`, `scroll`, веса и отступы в «дизайн-единицах» (dp).
- **Nine-slice панели** (`gui.set_slice9`) — панели растягиваются без искажения пиксель-арта.
- **Виртуальная сетка:** layout считается от «безопасной области», а не от краёв экрана.
- **Перестройка на лету:** слушаем `WINDOW_EVENT_RESIZED`, пересчитываем rect'ы, не пересоздавая экран.
- **Целочисленный скейл мира:** пиксель-арт рендерится с `floor(scale)`, чтобы не мылить.
- **Экраны описываются декларативно** (Lua-таблица: узлы и правила), а не кодом на каждый экран.

### 4.3 Портрет и ландшафт: правила раскладки

| Экран | Портрет (9:16 … 3:4) | Ландшафт (4:3 … 21:9) |
|---|---|---|
| Аванпост | вертикальный список: ресурсы сверху, слоты профессий колонкой | 2 колонки: слева слоты, справа очередь и события |
| Профессии | 1 колонка карточек | сетка 2×2 карточек |
| Крафт | список + кнопка снизу (большая, под большой палец) | список слева, детали и кнопка справа |
| Чат | отдельная вкладка на весь экран | боковая панель справа поверх мира |
| Аукцион | таблица, 4 видимые строки | таблица, 8–10 строк |
| Босс/волна | полноэкранная модалка | модалка по центру, мир виден по краям |

Дополнительно:
- **Портрет — основной режим** (одной рукой, большой палец достаёт до нижних 60% экрана).
- **Ландшафт — «режим обзора»**: игрок разворачивает телефон, чтобы посмотреть мир/аукцион/чат.
- **Safe area:** вырез, «динамический остров», жесты, скругления — отступы 16 dp сверху/снизу в портрете.
- **Минимальная тап-цель 44 dp**, никаких ховеров и тултипов «по наведению» — только долгий тап.
- **Планшет/складной:** тот же layout, но с максимальной шириной контента (иначе всё растянется).
- **Web:** те же breakpoints, `fullscreen`-кнопка, обработка ресайза окна и смены ориентации.

### 4.4 Отладочный веб-клиент (для проверки без Defold Editor)

Небольшой canvas-клиент (HTML + JS, без фреймворков), который говорит с тем же сервером по тому же протоколу.
Задачи: проверять геймплей и баланс, ловить ошибки протокола, показывать вам живой прогресс в браузере.
Он **не** заменяет Defold-клиент и не идёт в прод — это инструмент разработки.

### 4.5 Симулятор баланса

Node-скрипт без зависимости от клиента и сервера: берёт `shared/configs/*.json` и прогоняет сутки/недели
игры по разным архетипам. Выдаёт: время до тиров, кривые дохода, «узкие места» прогресса,
дисбаланс между платящими и нет. Балансим числами в конфигах, а не правкой кода.

## 5. Сервер и архитектура

### 5.1 Почему Node.js + TypeScript

- Один язык и один набор конфигов для сервера и инструментов (симулятор, генераторы).
- Для idle-игры нет хардкорных требований к CPU: расчёты ленивые, по запросу, а не по тику.
- WebSocket-библиотеки зрелые, деплой простой (один контейнер), порог входа низкий.
- Если позже упрёмся в CPU — «горячие» модули можно переписать, протокол не изменится.

### 5.2 Структура репозитория

```
/client      -- Defold-проект
/server      -- Node + TS: gateway, game logic, persistence
/shared
  /protocol  -- схемы сообщений, версии, генерация типов
  /configs   -- предметы, профессии, монстры, события (единый источник правды)
/tools       -- симулятор баланса, генератор Lua-таблиц, скрипты деплоя
/docs        -- этот файл и спеки
/.github     -- CI: сборка web и APK
```

### 5.3 Серверные модули

| Модуль | Ответственность |
|---|---|
| `gateway` | WSS, авторизация по токену, сессии, rate-limit |
| `state` | состояние игрока: навыки, инвентарь, очереди, буффы |
| `sim` | ленивые расчёты: сколько накопилось, что завершилось, пока игрок офлайн |
| `economy` | крафт, цены, аукцион, комиссия, антиинфляционные стоки |
| `world` | другие игроки в зоне, события, волны, босс |
| `social` | чат, гильдии (post-MVP), жалобы/мьюты |
| `admin` | выдача по промокодам, баны, метрики |

### 5.4 Модель времени

- Единственный источник времени — сервер (`Date.now()` в БД-транзакции).
- При входе: `sim.settle(player)` — «доводит» состояние до `now` (завершает крафты, начисляет добычу).
- Фоновый «ticks» не нужен для прогресса игрока; отдельный лёгкий цикл (раз в 10 сек) — для мировых событий.
- Идемпотентность: каждое действие имеет `request_id`, повтор не начисляет дважды.

### 5.5 Протокол (черновик)

Транспорт: WebSocket, JSON в MVP (потом — бинарный, если понадобится).

**Клиент → сервер**

```json
{"t":"hello","v":1,"token":"...","device":"android"}
{"t":"collect","rid":"uuid","skill":"wood"}
{"t":"craft_start","rid":"uuid","recipe":"axe_t2"}
{"t":"expedition_start","rid":"uuid","id":"forest_run","hours":2}
{"t":"market_list","rid":"uuid","item":"wood_t1","qty":50,"price":120}
{"t":"chat_send","rid":"uuid","ch":"world","text":"привет"}
```

**Сервер → клиент**

```json
{"t":"state","player":{...},"skills":{...},"queue":[...],"server_time":1793639406}
{"t":"delta","resources":{"wood_t1":120},"xp":{"wood":14},"server_time":...}
{"t":"event","kind":"void_wave","progress":0.62,"ends_at":...}
{"t":"chat","ch":"world","from":"Pilot","text":"...","ts":...}
{"t":"error","rid":"uuid","code":"RATE_LIMIT","msg":"..."}
```

Правила: сервер **никогда** не доверяет числам от клиента; версия протокола в `hello`;
несовпадение — принудительное обновление клиента.

### 5.6 База данных (SQLite → PostgreSQL)

```sql
players(id, nick, token_hash, created_at, last_seen_at, flags)
player_state(player_id, data_json, version)          -- быстрый снапшот
player_resources(player_id, item, qty, updated_at)
craft_queue(player_id, id, recipe, starts_at, ends_at, state)
market_listings(id, seller_id, item, qty, price, created_at, state)
market_sales(id, listing_id, buyer_id, qty, price, fee, sold_at)
world_events(id, kind, starts_at, ends_at, data_json)
ledger(id, player_id, item, delta, reason, ref, created_at)  -- аудит всей экономики
```

`ledger` — обязателен: без аудита экономику в MMO не починить (инфляция, дюпы, читы).

### 5.7 Деплой

`docker-compose`: `gateway` (Node), `db` (Postgres), `caddy` (TLS + WSS + раздача web-сборки).
Один VPS на старте. Метрики — Prometheus-совместимые эндпоинты + простой дашборд.

## 6. Монетизация (внешняя)

### 6.1 Принцип

Внутриигровые покупки идут **не через сторы**, а через внешний веб-магазин: игрок заходит на сайт,
покупает пакет, получает **промокод**, вводит его в игре — сервер начисляет награду.
Аккаунт один: тот же `player_id` на web и в игре.

```
игра (Android) ──логин──► сервер ◄──логин── веб-магазин
                              ▲
                       промокод / вебхук платёжки
```

### 6.2 Что продаём (не pay-to-win)

| Товар | Влияние | Обоснование |
|---|---|---|
| Буст оффлайн-кэпа (8→12 ч) | удобство | не даёт преимущества в бою |
| Доп. слот профессии/крафта | удобство | ускоряет, но не открывает эксклюзив |
| Косметика: скины аванпоста, рамки, титулы | 0 влияния | основной безопасный источник |
| Сезонный пропуск: задания + косметика | умеренное | выдаётся за активность, не за деньги напрямую |
| Пакеты ресурсов | **не продаём** | ломает экономику и PvP-баланс |

### 6.3 Технические требования к монетизации

- Выдача только сервером, по подписанному промокоду (HMAC + `jti`, одноразовость в БД).
- Вебхук платёжки → `grant` в очереди → идемпотентное начисление по `payment_id`.
- Лимит: один промокод на аккаунт, срок жизни, журнал в `ledger`.
- Никаких «секретных» ключей в APK: клиент не знает ничего, кроме своего токена.

### 6.4 Риски сторов (важно)

- **Google Play** ограничивает продажу цифровых товаров вне биллинга; в ряде регионов (включая РФ)
  платные сервисы Play фактически недоступны, но правила модерации всё равно применяются.
  Практика: в Play-сборке — только косметика/реклама без внешних ссылок на оплату, а полноценный
  магазин — на сайте и в сборке с прямой раздачи.
- **RuStore** и **прямая раздача APK** — самые спокойные каналы для внешней монетизации.
- Если позже захотим IAP — понадобится нативное расширение (`defold-iap`) и настройка товаров в консолях.
  В текущем плане этого нет.

## 7. Инструменты и CI

| Инструмент | Назначение |
|---|---|
| GitHub Actions `build-web.yml` | `bob.jar` → HTML5-сборка → артефакт/Pages |
| GitHub Actions `build-android.yml` | `bob.jar` + Android SDK/NDK → APK/AAB + подпись keystore из секретов |
| `tools/gen_configs.ts` | `shared/configs/*.json` → Lua-таблицы для клиента + TS-типы для сервера |
| `tools/sim.ts` | симулятор баланса |
| `dev-web` | отладочный браузерный клиент + локальный сервер |

Keystore генерируется один раз и хранится в секретах GitHub. **Потеря keystore = невозможность
обновлять приложение в сторе** — вынести в явный чеклист.

## 8. Дорожная карта

Оценки — в «рабочих сессиях» (условный день продуктивной работы), не в календарных сроках.

### Итерация 0 — Фундамент (2–3 сессии)
- Структура репозитория, `game.project`, `dynamic_orientation = 1`.
- Протокол v1 + генератор конфигов.
- Сервер: логин по токену, сессия, эхо-чат, `state`.
- Отладочный веб-клиент: логин + экран ресурсов.
- **Готово, когда:** два браузера логинятся, видят друг друга в чате, состояние сохраняется после рестарта сервера.

### Итерация 1 — Ядро idle (4–6 сессий)
- 4 профессии, 5 тиров, добыча по серверному времени, оффлайн-кэп.
- Инвентарь, крафт с очередью, экспедиции.
- Симулятор баланса, первые прогоны, правка чисел.
- Defold-клиент: экран аванпоста + профессии, layout-библиотека v1.
- **Готово, когда:** можно играть цикл «забрал → улучшил → поставил очередь → вернулся через час».

### Итерация 2 — Соц (3–4 сессии)
- Мировой чат, личные сообщения, модерация (мьют/репорт).
- Профиль игрока, лидерборды по профессиям.
- **Готово, когда:** на сервере 20 тестовых аккаунтов, чат живёт, есть модерация.

### Итерация 3 — Мир (5–7 сессий)
- Общий шард: видно аванпосты других игроков (лёгкая синхронизация позиций).
- Аукцион с комиссией и защитой от накрутки.
- Волна Пустоты и мировой босс по расписанию, награда по вкладу.
- **Готово, когда:** 50 тестовых игроков одновременно участвуют в событии, экономика не ломается за неделю.

### Итерация 4 — Мобильная сборка и релиз-кандидат (3–4 сессии)
- Адаптивный UI: портрет/ландшафт, safe area, целочисленный скейл.
- CI: web + APK, подпись, версии, changelog.
- Веб-магазин + промокоды + вебхук платёжки (тестовый режим).
- Онбординг, туториал, аналитика (события входа/удержания).
- **Готово, когда:** APK ставится на телефон, крутится в обеих ориентациях, покупка по промокоду доходит до аккаунта.

### Post-MVP
Гильдии, асинхронный PvP, сезоны и сбросы, пуш-уведомления, локализация, iOS (если появится Mac).

## 9. Риски

| Риск | Вероятность | Что делаем |
|---|---|---|
| UI в Defold съест больше времени, чем геймплей | высокая | layout-библиотека с 1-й итерации, декларативные экраны |
| Баланс «поплывёт» после релиза | высокая | симулятор + правки только в конфигах + ledger для аудита |
| Мало контента → игроки уходят через неделю | средняя | тиры + события + сезонность; контент-конвейер в конфигах |
| Модерация чата в MMO | средняя | мьют/репорт/фильтр с итерации 2, не «потом» |
| Политика сторов против внешней оплаты | средняя | разные сборки/каналы, косметика в Play, магазин на сайте |
| Web-сборка тяжёлая для мобильных браузеров | средняя | web = лайт-клиент, отдельный пресет качества |
| Потеря keystore | низкая/критичная | секреты GitHub + оффлайн-бэкап + чеклист релиза |
| Читы через подделку клиента | средняя | сервер авторитарен, никаких чисел с клиента |

   но полностью играбельный: 1 профессия, 1 крафт, чат, событие) и проверяем на живых людях?
